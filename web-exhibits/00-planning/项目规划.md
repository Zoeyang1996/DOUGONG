# 四幕独立互动网站项目规划

唯一需求基线：用户《斗拱11_11网站想法.md》，2026-11-11。保留原定四幕，不采用此前四幕推荐方案。本目录为本地设计与素材准备阶段，不发布。

## 交付结构

每幕独立 index.html，可独立启动；本轮三个 design-demo 页面就是各幕 index.html。共享资源保持相对路径，部署时随目录一起复制。独立HTML入口不等于把模型、代码全部内嵌一个文件。第四幕只建空壳和空题库。

每幕正式开发前固定交付：框架说明 → 可操作视觉demo → 素材与模型状态 → 分步实现及测试记录。本轮完成前三幕的这些前置材料。demo并非正式景区系统，文案与模型未定稿。

## 分阶段执行

1. 当前：建立目录、需求追踪、素材台账、三个视觉交互样稿、Blender源资产与网页模型。检查浏览器可加载和主要操作。
2. 第一幕正式制作：按六段脚本逐段核史，制作相机分镜和工具/建筑节点模型；先打通第一段，再推进六段。
3. 第二幕正式制作：先定收录标准，再做中国省份统计和全球时间维度。海外建筑不套用中国朝代标签；对比时可用公元年代区间。
4. 第三幕正式制作：保留60/30/20秒，逐关以件数、提示、吸附范围控制难度。完成规则测试，再换正式铺作GLB。
5. 第四幕留空。部署硬件、横屏分辨率、离线服务与现场恢复规则在集成阶段验证。

## 必须说明的边界

- 姓名不是可靠身份凭证：同名会合并次数、改名可绕过。demo按浏览器本地姓名+Asia/Shanghai日期计次。清理存储或换设备会重置，不能声称防作弊。正式方案可接统一服务或游客凭证，保留姓名输入。
- 一次尝试从点击开始第一关扣除，包含后续三关；失败、退出、刷新仍消耗该次。成功过关计时在“进入下一关”时启动。
- 左侧空白拖动旋转；从右侧拿构件后锁住旋转，只处理构件拖放；释放后恢复，避免触控手势冲突。
- 省份数字默认显示“本项目已收录样本”，不是现存木构总量。正式总量需要清单、范围、统计时间与出处。
- 日本“宁波工匠建寺”线索单列待查，未得到建筑、工匠、年代的可靠出处前不做事实卡。
- 旧md与历史模型都是参考素材，不是已验证结论；不沿用未经核证的坍塌推断、绝对无钉说法和伪精确结构数字。

## 验收

每幕可独立从首页进入、重置、结束；无跨幕解锁。所有依赖本地化。网页模型在触屏上可拾取、旋转、缩放，图文有来源。关卡验证计时、每日两次、成功/失败与重载。全景模型先优化再上线，不能把现有数千对象草模直接作为性能达标资产。
