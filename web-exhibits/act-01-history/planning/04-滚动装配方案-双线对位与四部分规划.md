## 一、先明确定义：什么是"装配轨"

原方案是"相机在三维空间里穿梭，六段各有一个镜头"。新机制的动词变了：**不是镜头移动，是物体自己完成、然后坠落让位。**

我把它定义成一条垂直的装配轨（assembly rail）：

```
        ↑ 上方滑入（下一组）
   ┌───────────────┐
   │   舞台中心     │  ← 固定不动。永远是 (0,0,0)
   │  一组零件在此   │     滚动只驱动"装配进度"，不动相机
   │  由散落到合拢   │
   └───────────────┘
        ↓ 完成后坠落（本组离场）
```

**三条硬规则：**

1. **舞台中心永不动。** 相机位置全程固定（只有极小的呼吸位移），六组模型都在同一个原点完成装配。这跟原方案相反，但正是"中心始终有一组零件"的实现方式。
2. **滚动 = 时间轴，不是位置。** 所有动画都由连续滚动值 `p ∈ [0, 6)` 单向计算得出，不累积状态。这样向上滚回看时，已经坠落的组会"倒着重演"，不会出现状态错乱。
3. **一组 = 一个历史阶段。** 构件数量随阶段递增（2 → 24 件），复杂度的爬升本身就是时间感。

### 单组内部的四个阶段（每组占 1 屏 = 100vh）

| 阶段 | 局部进度 t | 发生什么 |
|---|---|---|
| 入场 | 0 → 0.14 | 本组从上方 +Y 滑入，轻微过冲回弹；上一组的残影同时坠出 |
| 装配 | 0.14 → 0.62 | 构件按顺序错峰飞入位姿，每件间隔 0.12s；先结构后附件 |
| 停留 | 0.62 → 0.78 | 装配完成。**唯一允许用户拖拽观察的窗口**；文字同步可读 |
| 坠落 | 0.78 → 1.0 | 整组加速下落 + 微旋转 + 淡出；同时下一组已在顶部待命 |

**为什么坠落要快（0.55s）而入场要慢（0.5s）**：坠落是"退场"，观众不需要看清；入场是"登场"，要看清它从哪来。一快一慢，节奏才不平。

**坠落的语义**：不是"失败掉落"，是"一次完成，交给下一个时代"。这个隐喻要在文案里点一句，否则观众会以为物体散了。

## 二、双线对位表（本文核心）

明线 = 手上的零件从简单拼到复杂；暗线 = 斗拱从无到有、从承重到装饰。两线在**每一个滚动节点上同步换挡**，节点数与构件数一致：**6 组 = 6 段**。

| # | 滚动节点 | 明线：中心装配什么 | 件数 | 暗线：讲什么 | 时代锚点 | 两线的"扣"（一句话对应） |
|---|---|---|---|---|---|---|
| G1 | 01 榫卯初见 | 一榫一卯：榫件沿轴向插入卯件，合拢后可横置观察 | 2 | 木件如何相接 | 河姆渡文化（约 7000—5000 年前） | **有了"接"，才可能有"叠"** |
| G2 | 02 走入生活 | 柱—梁节点：梁头燕尾榫插入柱身卯口，加一枚木销锁定 | 4—5 | 从工具接合到建筑接合 | 新石器晚期—先秦（干栏建筑） | **同一个原理，从手柄走到房梁** |
| G3 | 03 斗拱之始 | 一斗二升（早期斗拱雏形）：栌斗上承横栱，两端各置散斗，上托一根短枋 | 5—6 | 柱头与屋檐之间为什么多出一组木件 | 汉代（陶楼明器所见） | **把"接"竖起来，变成"叠"** |
| G4 | 04 斗拱之变·唐 | 佛光寺东大殿柱头铺作（简化形制）：出跳多、构件粗壮、朵距疏 | 12—16 | 斗拱与梁拉结成整体，成为铺作层 | 唐·857 | **从"一件托架"变成"一层框架"** |
| G5 | 05 斗拱之变·宋 | **保国寺大殿前檐柱头铺作**：七铺作双杪双下昂，第一跳偷心；栌斗随柱做八瓣 | 18—24 | 《营造法式》把经验写成制度；材分模数、3:2 断面 | 北宋·1013 | **形制最完整的一朵，就在保国寺** |
| G6 | 06 由结构到装饰 | 清式平身科（简化）：斗拱变小、变小密，构件变薄 | 14—18 | 梁压在斗拱之上，斗拱不再承重，转为等级标识 | 清·1695 重建（太和殿） | **同样叫斗拱，它已经不承重了** |

### 三点必须注意

1. **G6 件数少于 G5，但复杂度更高。** 清式虽然构件变小，但组合更密。所以不能用"件数"单独表达难度，要在装配节奏上体现：G6 的构件飞入更快、更密（间隔 0.07s），视觉上"扎堆"，与唐式的"疏朗"形成对比。
2. **G4→G5→G6 必须是三个不同模型，不是同一个缩放。** 这是既有规划里已经写死的原则（"不用一个模型缩放冒充历代演变"），继续遵守。
3. **G1→G2→G3 是"原理递进"，不是"文物递进"。** 前三组标注"原理示意"，只有 G5 是真实的保国寺铺作。这个区分要在右上角的资产标签上写明，否则会被误读成"汉代就有这样的斗拱"。

## 三、视觉方案

### 3.1 布局：从"左右分栏"改成"中心舞台 + 角落文字"

现有实现是左侧 48% 文字、右侧 55% 固定舞台。新机制要求物体在**画面正中**，所以布局必须改：

```
┌──────────────────────────────────────────────┐
│  木构之间 / 01 一木相接            01 —— 06   │  ← 顶栏 84px，沿用现有
│                                              │
│                                    ┌────┐    │
│              舞台中心              │ 年代│    │  ← 右侧竖排年代标尺
│            （物体常驻）            │ 标尺│    │     宽 72px
│                                    └────┘    │
│  ┌─────────────────┐                         │
│  │ 01 / 榫卯初见   │                         │  ← 左下文字卡
│  │ 标题 + 主文案   │                         │     宽 380px，距底 80px
│  └─────────────────┘                         │
│                              ┌──────┐        │
│                              │证据图 │        │  ← 右下"证据角标"
│                              └──────┘        │     120×80
├──────────────────────────────────────────────┤
│ ▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ │  ← 底部进度条 3px
└──────────────────────────────────────────────┘
```

**为什么文字放左下而不是居中**：中心必须让给物体。左下是视线扫过后的落点，不抢中心。宽 380px，避免大段文字横跨画面。

**年代标尺（右侧竖排）**：六个时代名，当前高亮。它是暗线的"外置仪表盘"——明线在中心动，暗线在右侧告诉你在哪个时代。滚动时标尺同步下移。

### 3.2 配色（沿用现有变量，不新造）

| 用途 | 值 | 说明 |
|---|---|---|
| 纸底 | `#f1ede3` | 沿用 `--paper` |
| 墨 | `#292d27` | 正文与标题 |
| 赭红 | `#9a4c2e` | 强调、当前节点、进度条 |
| 木深 | `#845238` | 卯件 / 深色构件 |
| 木浅 | `#a36c43` | 榫件 / 浅色构件 |
| 线 | `#d6d0c0` | 分隔线、标尺刻度 |
| 台面光 | `radial-gradient(ellipse at 50% 46%, #e6dcc8 0%, transparent 62%)` | 中心舞台的"聚光"，比纯纸底多一层体积感 |

**G5 保国寺专属色**：给这一组加一个极克制的区分——构件用同色木，但**栌斗的八瓣轮廓用赭红描一条 1px 线**。全篇只有这一处有描边，形成视觉焦点。不额外加色。

### 3.3 运动参数（可直接照抄进代码）

| 动作 | 时长 | 缓动 | 位移 / 其他 |
|---|---|---|---|
| 构件飞入（单件） | 320ms | `easeOutCubic` | 从 offset 到 0，offset 由资产元数据给出 |
| 构件错峰间隔 | 120ms（G1—G3）／ 80ms（G4—G6） | — | 前面几组慢，后面几组快 |
| 整组入场 | 500ms | `easeOutBack`（过冲 1.04） | 从 +Y 2.6m 到 0 |
| 整组坠落 | 550ms | `easeInQuad` | 至 -Y 2.4m，绕 Z 轴 0.12rad，opacity 1→0（后 30%） |
| 相机呼吸 | 全程 | — | 位置 ±0.05m，周期 8s，极慢，避免画面死 |

**一个反直觉但正确的做法**：坠落**不做**模糊。模糊会让"时间流逝"变成"故障"。用加速下落 + 淡出就够了。

### 3.4 交互：拖拽与滚动的冲突必须提前解决

用户要求"可拖拽从三维视角观察"。但全屏 `OrbitControls` 会吃掉滚动手势——这是触屏上最容易翻车的地方。

**方案：方向判定 + 限幅旋转**

```
pointerdown → 记录起点
pointermove → 若 abs(dx) > abs(dy) × 1.5 且 abs(dx) > 6px  → 进入旋转模式（锁定页面滚动）
              否则                                          → 放行给页面滚动
旋转时：只允许 yaw ±35°、pitch ±18°，不可缩放，不可平移
pointerup  → 松开后 400ms 内缓动回正
```

**为什么限幅**：无限旋转会让物体转到背面，观众就找不到"重点在哪"。限 35° 足够看清厚度和搭接，又不失去方向感。

**为什么回正**：下一个节点开始时，物体必须回到标准视角，否则六组的观看角度不一致，无法比较。

### 3.5 三处"看得见的诚实"

这个项目评审最在意"有没有把示意当复原"。用三个固定 UI 元素解决：

1. **资产类型标签**（右上角，小字）：`原理示意` / `形制示意` / `保国寺实例`
2. **比例尺**：G4—G6 显示 `同比例对照` 或 `轮廓对照，非同比例`
3. **证据角标**：右下小图 + 一行来源，点开放大（见第五节）

### 4.2 六组文字草案

**G1｜榫卯初见**
- 标题：木头，怎样握住另一块木头？
- 主文案：木件上的凸起叫榫，凹口叫卯。一凸一凹，咬合即成连接。河姆渡出土的木构件，留下了这种接合最早的实物证据。
- 关键变化：**有了"接"，才可能有"叠"。**
- 标注：原理示意（不对应单件出土器物）

**G2｜走入生活**
- 标题：从手里的柄，到房子的梁。
- 主文案：工具需要装柄，房屋需要立柱架梁。同一个榫卯原理，从器物走上建筑。干栏建筑把居住面架空，柱、梁、板靠节点连成整体。
- 关键变化：**同一个原理，从手柄走到房梁。**
- 标注：原理示意（干栏为结构示意，非某座遗址复原）

**G3｜斗拱之始**
- 标题：屋檐下，为什么多出一组木件？
- 主文案：柱顶到屋檐之间，多了一叠木块。栌斗承横栱，横栱两端置散斗，再托起上面的枋。东汉陶楼上，已经能看到这样的形象。
- 关键变化：**把"接"竖起来，变成"叠"。**
- 标注：原理示意（据汉代明器形象；陶楼为陶制明器，非留存木楼）

**G4｜斗拱之变·唐**
- 标题：从一件托架，变成一层框架。
- 主文案：唐代的斗拱与梁拉结成整体，一圈柱头枋与梁交织成水平框架。斗拱体量接近柱身一半，出檐可达三四米。
- 关键变化：**从"一件托架"变成"一层框架"。**
- 标注：形制示意（佛光寺东大殿柱头铺作，唐 857）

**G5｜斗拱之变·宋**
- 标题：形制最完整的一朵，在这里。
- 主文案：保国寺大殿建于 1013 年。前檐柱头铺作七铺作双杪双下昂，第一跳偷心；栌斗随柱身做成八瓣。九十年后，《营造法式》成书。
- 关键变化：**形制最完整的一朵，就在保国寺。**
- 标注：保国寺实例（形制与尺寸待最终核校）

**G6｜由结构到装饰**
- 标题：同样叫斗拱，它已经不承重了。
- 主文案：明清的梁不再插入斗拱，而是压在斗拱最上一跳。斗拱尺度缩小、间距加密，构件厚度减至唐宋的二分之一，转而标示等级。
- 关键变化：**同样叫斗拱，它已经不承重了。**
- 标注：形制示意（太和殿平身科，康熙重建形制）

## 五、图片资料来源与使用方式

### 5.1 核心决策：这一版图片是"证据角标"，不是"主体画面"

原方案里图片承担很大的叙事份额（陶楼、干栏、工具各一张）。但滚动装配机制下，**中心的 3D 零件才是主角**。图片如果大幅出现，会和 3D 抢视线，也会让"我在看模型"变成"我在看 PPT"。

所以定了：**每屏最多 1 张小图，固定在右下角，120×80，带来源标签。点击放大到 360×240 并显示完整出处。**

这个对照关系本身就是叙事：**"中间是我搭的模型，右下是它真实存在的证据。"**

| **A5** | G5 | **保国寺前檐柱头铺作**（七铺作双杪双下昂单偷心） | 18—24 | ★★★ 核心 | `baoguosi-bracket.glb` 草模，**需重新核校拆分** |
| **A6** | G6 | 清式平身科（简化） | 14—18 | ★ | 无 |

**总件数上限约 70 件。** 这是可接受的：`assembly-demo.glb` 已验证 10 件独立件的拾取与拖放，70 件分组常驻不会带来性能问题（关键在材质合并与 drawcall 控制）。

### 6.2 装配元数据规范（这是本次新增的硬要求）

现有约定只要求"稳定 id、中文名称、来源、审核状态"。装配机制需要**额外四个字段**，建议直接写进 GLB 的 `extras`，或独立 JSON：

```json
{
  "id": "a5_ludou_01",
  "name_cn": "栌斗",
  "group": "A5",
  "order": 1,
  "appear": { "offset": [0, 1.6, 0.8], "rot": [0.3, 0.4, 0] },
  "target": { "pos": [0, 0, 0], "quat": [0, 0, 0, 1] },
  "type": "实例",
  "source": "保国寺大殿前檐柱头铺作（据东南大学测绘）",
  "status": "待核",
  "note": "栌斗随柱身做八瓣，现存遗构唯一案例"
}
```

- `order`：装配顺序。**必须由构造关系给出**（先下后上、先主后次），不能按显示层数自动推断——这是既有台账里已经写明的纪律。
- `appear.offset`：构件起始位置。建议统一从"上方 1.2—1.8m + 侧向散布"进入，形成"从天而降、落位"的统一语法。
- `target`：最终位姿。建模时以舞台原点为基准，**每件都在最终位置建模**，导出时自带正确 transform。

### 6.3 建模六条硬规范

1. **单位米，原点在舞台中心**（地面 y=0），一组内所有构件共用同一坐标系。
2. **每件独立 Object，不 join。** 否则无法逐件装配。
3. **材质合并**：同色构件共用材质，避免 70 个材质拖垮性能；但**高亮用 emissive 时须 clone**，否则会全亮。
4. **不要建隐蔽榫口。** 装配是"落位"，不是"演示内部咬合"。内部结构看不到，不建。
5. **单组 GLB < 3MB**，Draco 压缩；贴图最大 1024。
6. **G1—G3 标"原理示意"，G5 标"保国寺实例"**，标签写进 `status` 字段，前端读出来直接显示在右上角。

### 6.4 三组最该先做的

| 顺序 | 资产 | 理由 | 工作量 |
|---|---|---|---|
| 1 | **A1** | 已有实切模型，补动画即可打通整条流水线（装配→坠落→入场），**先验证机制再做内容** | 0.5 天 |
| 2 | **A3** | 件数适中（5—6），是"从简单到复杂"的转折点，也是唯一能低成本验证"多件错峰"的组 | 1.5 天 |

## 七、与现有实现的差异（迁移清单）

| 项 | 现在 | 改成 | 影响 |
|---|---|---|---|

## 八、风险与止损

| 风险 | 表现 | 止损 |

| 六组建模做不完 | 到中期只有 2—3 组 | A2/A4/A6 用简化方块占位，保住六段叙事完整 |
