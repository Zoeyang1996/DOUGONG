## 产出：网站交互制作指导文档

- 新建 `网站的创意想法-交互制作指导.md`（根目录，约 720 行）。
- 来源：解析 `网站的创意想法.docx`（用户手写的科普段 + 游戏段构想），结合 `research/` 已有研究底稿扩展成施工图。
- 七幕结构：入口 → 榫卯 → 三千年 → 现存名构 → 解剖 → 三例对比 → 四款游戏 → 收尾。
- 关键设计判断（后续不要推翻）：
  1. 科普段与游戏段不能只是前后拼接，游戏是"验证理解"的手段，不是奖励。
  2. 三例铺作定为 佛光寺（唐 857）/ 独乐寺（辽 984）/ 保国寺（北宋 1013），正好卡三阶段叙事节点，同一比例尺并排。
  3. 拼接游戏只考"顺序 + 位置"，**不做朝向判定**（触屏精细旋转是灾难）；难度来自"下层就位才亮上层插槽"的顺序约束。
  4. 抽件游戏**不做实时刚体物理**（榫卯是半刚性节点，必然穿模且结果不唯一），改为「预计算失稳表 + 3 条预烘焙崩塌动画」，构件标 `structural: primary/secondary/stabilizer/ornament`。
  5. 拆分屏双人时不能用同一 scene，需两 scene 或双 viewport，因此该关必须用低模。
- 资产杠杆：`models/baoguosi_zhutou_v01/parts_manifest.json` 已有 59 件构件，带 id/name/layer/location，可直接生成拼接关的答案表 `assembly.json`，无需人工标注。
