## 三、三个技能点（只演示这三个）

### 技能点 1 · 球面坐标与屏幕投影

| 项 | 内容 |
|---|---|
| 一句话 | 经纬度 → 球面三维点 → 屏幕坐标，红点和地名签共用一套 |
| 现场动作 | ① VSCode 指 `data.json` 三个关键字段 ② 切浏览器点一座建筑的地名签 ③ 拖地球，让评委看标签跟着转 |
| 演示时长 | 120 秒 |
| 判断标准 | 标签始终贴着自己的红点；球背面不显示；点击容差 ≥30px |
| 易错 | 标签与红点用两套坐标，一转就错位 |
| 出问题时 | 标签不显示 → 直接拖地球讲“它们是一起动的” |

**关键代码位置**：`js/globe/globe.js` 的 `view.project(lat, lon)`。

**说这三句就够**：

> 每条建筑就是一个经纬度。我先把它换成球面上的三维点，再投影成屏幕坐标。
> 红点和地名签用的是同一套坐标，所以球一转，它们一起动，不会错位。
> 背面的点要判掉，不然会显示在正面上。

### 技能点 2 · 不裁切与 DOM/WebGL 混合布局

| 项 | 内容 |
|---|---|
| 一句话 | 画布做得比舞台更大，球再放大也不会被切 |
| 现场动作 | ① 切 DevTools，改 `--bleed` 或舞台宽度 ② 让评委看球与左侧文字的关系变化 ③ 改回来 |
| 演示时长 | 90 秒 |
| 判断标准 | 任何缩放级别整球可见；左侧说明栏压在球上时层级清楚 |
| 易错 | 画布与容器同尺寸 → 一放大就被切平；用 `overflow:hidden` 裁掉 |
| 出问题时 | DevTools 改坏了 → 刷新页面，口头解释 |

**改什么**：在 Elements 面板选中 `.earth-stage`，把 `--bleed` 从当前值改大，球会向左延伸进文字区，但整个球仍在画布内。

**说这三句就够**：

> 球一放大就被切平，原因是画布和容器一样大，球超出画布就被裁。
> 改法是画布比舞台更大：右缘对齐，左缘外扩，扩出去的部分正好藏到左边说明栏下面。
> 每帧读一次舞台边界，换算成画布坐标，交给标签层对齐。

### 技能点 3 · 四级镜头状态机

| 项 | 内容 |
|---|---|
| 一句话 | 四级不是四个页面，是同一个场景的四个距离；返回逐级退 |
| 现场动作 | ① 首页 → 点中国 → 点唐 → 点佛光寺 → 点图片开三维 → 叉叉关 → 点返回 → 再返回 |
| 演示时长 | 180 秒（全场最重要的一次演示） |
| 判断标准 | 每次点击都有可见的镜头变化；返回回到上一级而不是首页 |
| 易错 | 三四级传了相近距离，点了像没反应 |
| 出问题时 | 某级卡住 → 直接点“复位”重来，别在原地试 |

**四级与镜头的关系**：

| 级 | 触发 | 球的目标大小 |
|---|---|---|
| 一级 全球 | 初始 / 复位 | 最小 |
| 二级 地区 | 中国 / 日本 / 欧洲 | 中 |
| 三级 朝代 | 唐 / 宋 / 辽… | 大 |
| 四级 单座 | 某座建筑 | 最大 |

**为什么点“唐”会转到山西**：落点取该朝代所有条目的重心，唐代条目多在山西。

## 七、被追问时怎么答

| 问题 | 怎么答 |
|---|---|
| 为什么不用框架 | 要离线、要小。原生 ES 模块足够，省掉构建和依赖。 |
| 球为什么不会跑出屏幕 | 最近距离是按屏幕可用半径反推的，所有缩放都被夹在这个值上。 |
| 标签怎么跟着球转 | 每帧把三维点投影成屏幕坐标，标签只是绝对定位的按钮，不参与三维计算。 |
| 为什么不做成小程序 | 网页一个链接就能开，不用下载；离线要本地文件，小程序做不到。 |
| 代码有多少是 AI 写的 | 骨架和算法思路是和 AI 一起推的，落地、调试、改单位都是我做的。我要求它先解释再给代码，看不懂的不落地。 |
