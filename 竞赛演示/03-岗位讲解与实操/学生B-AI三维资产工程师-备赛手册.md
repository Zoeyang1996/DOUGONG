## 三、三个技能点（只演示这三个）

### 技能点 1 · 形制建模与场景清理

| 项 | 内容 |
|---|---|
| 一句话 | 按斗口模数建比例，再把文件清到“只剩建筑” |
| 现场动作 | ① Blender 里旋转柱头铺作，指出栌斗、栱、昂、散斗 ② 切大纲视图看物体数 ③ 讲清理前后的包围盒差异 |
| 演示时长 | 130 秒 |
| 判断标准 | 出跳数与照片一致；无相机灯光地面天空；最大边 10 单位；底面落地 |
| 易错 | 留着大地面 → 包围盒几百米 → 网页里建筑只有指甲盖大 |
| 出问题时 | Blender 打不开 → 切到浏览器点三维模型，讲“这个模型是怎么来的” |

**关键数字**：法隆寺地面 4400 米；东大寺一次删 64 个远处配景；太和殿 71 万面。

**说这三句就够**：

> 建模前先定一个基准——斗口。斗口定了，其余构件都是它的倍数，这是《营造法式》的模数制。
> 模型出来不能直接用，第一步是清场景：相机、灯光、地面、天空全删。
> 不删的话模型进网页只有指甲盖大——法隆寺光地面就有四千多米。

### 技能点 2 · 材质还原（本段最重要）

| 项 | 内容 |
|---|---|
| 一句话 | 把 Blender 的程序化颜色，变成 glTF 能认的基色 |
| 现场动作 | ① 展示全白模型截图 ② 回 Blender 指 Mix + ColorRamp 节点 ③ 讲烘焙写回 ④ 切浏览器看修复后 |
| 演示时长 | 200 秒 |
| 判断标准 | 瓦灰、木赭、石米三层次可分；无全白、无全黑 |
| 易错 | 直接导出全白；用顶点色在不同加载器表现不一致 |
| 出问题时 | 节点编辑器打开慢 → 直接讲现象与三步排查 |

**这是全场最有说服力的一段，按七步讲**：

1. 现象：第一次导出，十二座全白。
2. 查 glTF：材质在，但基色是 1,1,1。
3. 查节点：颜色来自 Mix 与 ColorRamp，不是基色。
4. 试错：烘到顶点色（COLOR_0），三个加载器里要么全 1 要么全 0。
5. 正解：Cycles 烘漫反射，按材质取均值写回基色。
6. 特例：金属没有漫反射色，烘出纯黑，回退原基色。
7. 结果：颜色是从模型自己身上取的，不是我猜的。

### 技能点 3 · 导出与体积控制

| 项 | 内容 |
|---|---|
| 一句话 | 618MB 压到 23MB，并且说清为此放弃了什么 |
| 现场动作 | ① 文件管理器按大小排序 ② 报三个数 ③ 浏览器看加载进度条 |
| 演示时长 | 130 秒 |
| 判断标准 | 单个 ≤7MB；总 ≤25MB；Draco 开启；不导贴图 |
| 易错 | 导了贴图体积爆炸；忘开 Draco 解码器路径对不上 |
| 出问题时 | 文件管理器慢 → 直接报数字 |

**三个数背下来**：

| 项 | 数值 |
|---|---|
| 源文件总量 | 618MB（13 个 .blend） |
| 产物总量 | 23MB（12 个 GLB） |
| 最大单件 | 太和殿 6.9MB / 71 万面 |
| 最小单件 | 北岳庙德宁殿 0.2MB |

**必须主动说的取舍**：

> 现在是“每个材质一个颜色”，没有贴图，近看瓦垄和木纹是平的。要有纹理得展 UV 烘贴图，单个模型会涨到 3—8MB。暂时没做，因为要保证普通笔记本上点开就能转。

## 四、完整台词

### 接场（12:00—12:20）

**【12:00｜B 上前，A 退到侧位；打开 Blender】**

好，我是学生 B，负责三维资产。

A 给我的清单是：十二座木构建筑，加一朵保国寺柱头铺作。**十三座建筑，十三个 Blender 文件。**

### 建模与清理（12:20—15:00）

**【12:20｜P14｜拖拽旋转柱头铺作】**

先看这个。这是保国寺的柱头铺作。

**【12:35｜放大，指构件】**

从下往上：最下面是栌斗，坐在柱头上；上面一层层是栱，横向的叫泥道栱、华栱，斜着往外挑的是下昂；栱和栱之间垫的小块叫散斗。

**【13:00】**

建模不是照着照片描。我先定一个基准——斗口，就是栌斗上那个承托的槽宽。斗口定了，其余构件都是它的倍数。这是《营造法式》的模数制，也是我保证比例不走样的办法。

**【13:25｜展开大纲视图】**

结构上按顺序建：台基、柱网、铺作、梁架、屋顶。一层一层往上，每层标高都对得上。这样后面改哪一层，不会牵连别的。

**【13:45】**

十三座里最大的是故宫太和殿，七十一万个面。最小的是北岳庙德宁殿，二十万个面不到。

**【13:55｜P15｜切大纲，指物体列表】**

模型建完只是第一步。真正难的是怎么让它进网页。

模型从 Blender 出来不能直接用。第一步是清场景：相机、灯光、地面、广场、参道、天空穹顶，全删。

**【14:20｜指物体数量】**

为什么要删？因为包围盒。这些配景会把整个模型的边界撑到几百米。法隆寺那个文件，光地面就有四千多米。不删的话，模型进网页，建筑只有指甲盖那么大。

东大寺更夸张，我一次删了六十四个远处的树和石头。

**【14:40】**

第二步是归一化：最大边缩到十个单位，底面落到零，原点居中。这样十二座建筑在网页里是同一个尺度，切换不会一大一小。

**【14:55】**

这两步做完，模型才算“能进网页”。

### 材质还原（15:00—20:00）

**【15:00｜P16】**

接下来这段，是我这次最难的一关。

**【15:05｜切浏览器，展示全白截图】**

第一次导出，十二座建筑，全是白的。

**【15:15】**

我以为是材质没导出去。打开 glTF 检查，材质在，但每个材质的基色都是 1、1、1，纯白。

**【15:30｜切回 Blender，打开节点编辑器】**

回来查节点。问题在这——颜色不是设在基色上，是连在节点上。这是一个 Mix 节点，混了两个 ColorRamp，ColorRamp 里是一串色标。

**【15:55｜指节点】**

**glTF 只认两样：一个基色值，或者一张贴图。它读不懂节点。**

所以导出的时候，颜色就丢了。

**【16:15】**

第一次尝试，是把颜色烘到顶点色上。就是给每个顶点存一个颜色。结果更麻烦——同一个文件，在三个不同的加载器里，有的显示全白，有的显示全黑。

顶点色这条路，不可靠。

**【16:40】**

第二次，改用 Cycles 烘一遍漫反射，每个材质烘出一张图，再把这张图的平均值，写回这个材质的基色。

**【17:00】**

这样颜色就从一个“节点网络”，变成了一个“值”，glTF 就能读了。

**【17:15】**

但还有一类是特例：金属材质。金属没有漫反射色，烘出来是纯黑。所以金属材质不走这条路，直接用回它原本的基色。

**【17:35｜切浏览器，展示修复后】**

最后的结果是这样。瓦是灰的，木构件是赭的，台基是米色的。三个层次都在。

**【17:55】**

**而且这个颜色不是我挑的，是从模型自己身上取出来的。**我没有为了好看去改颜色，我是把它原本的颜色救回来。

**【18:10｜过渡】**

颜色解决完，最后一个问题是体积。

### 导出与体积（18:10—20:00，接 P17）

**【18:10｜P17｜切文件管理器】**

十三个源文件，一共六百一十八兆。直接放网页，打开要等半分钟。

**【18:25｜指文件列表】**

我做了三件事：导出 GLB 格式，开 Draco 几何压缩，不导贴图、不导相机灯光。

结果：十三座变成十二座，六百一十八兆压到二十三兆。

**【18:55｜指最大最小】**

最小的是北岳庙，零点二兆；最大的是太和殿，六点九兆。太和殿面数太多，七十一万面，压不下去。

**【19:15】**

这里有个取舍要说清楚：**现在模型是“每个材质一个颜色”，没有贴图。**近看瓦垄、木纹是平的。

**【19:35】**

要做到有纹理，得展 UV、烘贴图，单个模型会从零点七兆涨到三到八兆。我们试过，暂时没做——因为要保证在赛场这种普通笔记本上，点开就能转，不能卡。

**【19:55】**

还有一个策略：模型不是一开始就加载。进详情页才加载图片，点开三维才请求模型，而且带版本号，改一次换一个号，浏览器不会读旧缓存。

**【20:15】**

三维这部分就到这。下面交给 C，讲网页怎么把这些接起来。

**【20:25｜交接】**

C，从数据结构开始。
