# 模型资产管线（从建模到上屏）

> 用途：四人协作时"A 同学交给 C 同学什么"的接口定义。管线不统一，集成必崩。

---

## 一、建模路线三选一

| 路线 | 做法 | 精度 | 时间 | 适用 |
|---|---|---|---|---|
| **① 手工建模（推荐）** | Blender 按测绘数据建 | 高、可控 | 长（一朵 3—5 天） | 主角"柱头铺作" |
| ② AI 图生 3D | 现场照片 → Tripo / 混元3D / Meshy → 修模 | 中低（拓扑脏） | 短（1 天） | 背景构件、远景大殿 |
| ③ 参数化生成 | three.js 里用代码拼几何体 | 中（尺寸可控但细节假） | 中 | 快速验证交互手感 |
| ④ 扫描重建 | 三维激光扫描点云 → 重拓扑 | 最高 | 很长 + 需设备 | 不现实（无设备、无授权） |

**建议组合**：主角用 ①，20 种斗拱的"谱系缩略图"用 ②（或 ①的低模简化版），交互原型阶段先用 ③ 占位。

> AI 生成 3D 的现实：拓扑混乱、榫卯结构不可信。**不要用 AI 生成的模型讲结构**，会被专业人士一眼看穿。AI 只用来做氛围与量。

## 二、Blender 端的硬性规范

### 1. 单位与坐标
- 场景单位：**米（Metric, Scale = 1.0）**
- 轴向：Y 轴向上（glTF 导出时 Blender 会自动转 Z-up → Y-up，保持默认即可）
- 原点：整朵斗拱的栌斗**底面中心**为世界原点 (0,0,0)。这样每朵都能直接叠放拼接。

### 2. 命名（与知识库文档一致）
```
gong_huagong_tiao1_01
dou_ludou_01
ang_xiaang_01
fang_zhutoufang_01
```
- 全小写、下划线、无中文、无空格
- 同一构件有多个实例时，尾号递增（`_01`、`_02`）
- **名字会一路带到 three.js 的 `userData.name`，是 UI 与 AI 的索引键**

### 3. 对象结构
- 每个构件 = 独立 Object（**不要** join 成一个整体，否则无法拆解）
- 不用的层级拍平，不要留空 Empty
- 应用全部变换（`Ctrl+A → All Transforms`），避免位置信息藏在矩阵里

### 4. 尺寸依据
| 构件 | 依据 |
|---|---|
| 材断面 | 单材 15 分 × 10 分；足材 21 分 × 10 分 |
| 栱长 | 泥道/瓜子 62 分、令栱 72 分、慢栱 92 分、第一跳华栱 60 分 |
| 出跳 | 每跳最长 30 分 |
| 大殿整体 | 面阔 11.91 m，进深 13.36 m，当心间 5.8 m |

**做法建议**：先在 Blender 里定一个"分"的实际长度（如 1 分 = 12 mm，则单材高 180 mm、宽 120 mm），全模型按这个模数推。这样比例天然正确。

### 5. 材质
- 每个构件独立材质（便于高亮，避免共享材质导致"一点全亮"）
- 贴图：**不要**用 4K。1024 足够；木纹用无缝平铺
- 材质简化：Principled BSDF，只保留 Base Color + Roughness，不要透射、不要 SSS

### 6. 导出
```bash
File → Export → glTF 2.0 (.glb)
  Format: glTF Binary (.glb)
  Include: Selected Objects / 或可见对象
  Transform: +Y Up ✔
  Data: Apply Modifiers ✔
  Geometry: UVs, Normals, Tangents(不需要就别勾)
  Compression: 不在这里压，用命令行压（可控）
```

## 三、压缩管线（必须做，否则大屏加载 10 秒）

```bash
# 0. 先体检：看清楚哪里占体积
npx gltf-transform inspect raw.glb

# 1. 一键优化（Draco 几何 + WebP 贴图 + 限尺寸）
npx gltf-transform optimize raw.glb puzuo.glb \
  --compress draco \
  --texture-compress webp \
  --texture-size 1024

# 2. 若还要更小：上 KTX2（Basis Universal）
npx gltf-transform etc1s puzuo.glb puzuo_ktx2.glb
```

**经验值**
| 项目 | 原始 | 优化后 |
|---|---|---|
| 一朵斗拱（约 50 构件） | 15—40 MB | **1.5—3 MB** |
| 全殿低模背景 | 100 MB+ | 5—8 MB |
| 开源古建项目参考 | 236 MB | 20 MB（Draco + WebP + Simplify） |

**注意**：Draco 需要 `DRACOLoader`，KTX2 需要 `KTX2Loader` + 转码器文件。**解码器必须放本地 `/public/decoders/`**，理由见交互规范篇（断网）。

## 四、构件元数据（关键设计）

每个构件的说明文字不要写在代码里，写在数据文件里，以模型名为主键：

`src/data/parts.js`
```js
export const PART_INFO = {
  "dou_ludou_01": {
    name_cn: "栌斗",
    pinyin: "lú dǒu",
    category: "斗",
    layer: 0,
    definition: "整朵斗拱最下面的那块大斗，坐在柱头上，承担全部重量。它的体积最大，大约相当于八个齐心斗。",
    detail: "保国寺大殿的栌斗随柱身做成八瓣，与瓜棱柱上下呼应——这是现存木构中的唯一案例。",
    source: "《营造法式》；中国宁波网《木构重辉》(2021)",
    tags: ["承重", "八瓣", "孤例"]
  },
  "gong_huagong_tiao1_01": {
    name_cn: "华栱（第一跳）",
    pinyin: "huá gǒng",
    category: "栱",
    layer: 1,
    definition: "垂直于墙面、向外挑出的栱。它每向外伸出一层，就叫'出一跳'。",
    detail: "保国寺前檐柱头铺作的第一跳华栱是'偷心'——跳头上不放横栱。",
    source: "《营造法式》；搜狗百科·宁波保国寺大殿",
    tags: ["出跳", "偷心"]
  }
  // ... 每个构件一条
};
```

**为什么这么设计**
1. 改文案不用改代码，不写代码的人也能改。
2. 直接作为 AI 问答的检索语料（按 `tags` / `name_cn` 召回）。
3. 答辩时可以展示"知识库与模型同源"，这是加分项。

## 五、交付清单（A 同学交给 C 同学时必须齐）

- [ ] `puzuo.glb`（Draco 压缩）
- [ ] `parts.js`（构件元数据，每构件至少 6 个字段）
- [ ] 构件总数与清单表（Excel/Markdown）
- [ ] 一张带尺寸标注的三视图渲染图（做 UI 里的"测绘图"风格背景）
- [ ] Blender 源文件（`.blend`，不进 Git，用网盘/共享盘）
- [ ] 命名与尺寸说明（1 页）

**验收口径**：构件数对不对、尺寸误差是否 < 2%、名字能否一一对上、单朵 GLB 是否 < 3 MB。

## 六、资产复用的三种方式（申报书"复用价值"要说清）

1. **跨平台复用**：同一 GLB，Web 端用 Draco 版，VR 端用原精度版。
2. **跨产品复用**：斗拱资产可用于短视频、AR 卡片、研学教具的 3D 打印、文创周边。
3. **跨课程复用**：进入《三维建模》《交互设计》课程案例库，形成"学生做的资产给下一届用"的循环。

> 答辩时用一句量化表述："一朵斗拱建模工时约 32 人时，复用后同类科普项目可节省约 70% 建模工时。"——**但数字必须来自你自己的实际记录，不能拍脑袋。** 所以从现在开始就记工时表。
