# Vibe Coding Prompt 库（可直接复制粘贴）

> 用途：这是我们实际干活的方式。把需求说清楚，让 AI 写代码；但**形制与数据必须由我们把关**。
> 原则：一次只让 AI 解决一件事；每个 prompt 都要给出"验收标准"。

---

## 一、通用开场（每次对话第一句都带上）

```
你是 three.js 资深开发者。我们在做宁波保国寺斗拱的三维科普交互页面，
目标设备是一台 4K 触摸屏（无键盘鼠标、可能断网），要求稳定 60fps。

硬约束：
1. 原生 three.js（不要 React/R3F），Vite 构建，模块化。
2. 所有资源本地路径，不用 CDN（运行时会断网）。
3. 触屏手势只允许：单指拖动旋转、双指缩放、点击。不要 hover 依赖。
4. 中文注释，变量名英文。
5. 每段代码之后告诉我：这段的性能风险在哪、在低配设备上会怎样。
```

## 二、任务 1：搭场景骨架

```
创建一个 three.js 场景：
- 深色背景（#131315），带雾气，营造博物馆低照度氛围
- 一盏半球光 + 一盏主方向光（投射阴影）+ 一盏补光
- PerspectiveCamera，fov 42，OrbitControls 开启阻尼，禁用平移，限制俯仰角
- renderer.setPixelRatio 上限 2（4K 屏必须限制，否则掉帧）
- ACES 色调映射，阴影贴图 2048，bias -0.0005 防阴影痤疮
- 监听 resize

验收：控制台无警告；窗口缩放时画面不变形；空场景 60fps。
```

## 三、任务 2：加载 GLB 并建立构件索引

```
用 GLTFLoader + DRACOLoader 加载 /models/puzuo.glb（Draco 压缩）。
加载完成后：
1. 遍历所有 mesh，开启 castShadow / receiveShadow
2. 记录每个 mesh 的初始 position 到 Map，供复位用
3. 每个 mesh 的名字形如 "gong_huagong_tiao2_01"，解析出：
   - 构件大类（dou/gong/ang/fang/shuatou/chenfang）
   - 跳数（tiao1..tiao4，无则 0）
   存入 userData
4. 加载完成后自动计算包围盒，把相机拉到合适距离

验收：console.table 打印出构件清单（名字、大类、跳数）；相机自动取景不穿模。
```

## 四、任务 3：爆炸视图（核心）

```
实现两阶段爆炸视图，用一个 0→1 的进度值 t 驱动：

阶段 A（t: 0→0.45）：分层平移
  构件按 userData.layer（0=栌斗层 … 6=衬枋头层）沿 Y 轴上移，
  每层偏移 = layer * 0.34 * (t/0.45)。同层构件保持相对位置。

阶段 B（t: 0.45→1）：径向散开
  在阶段 A 的位移基础上，每个构件再沿"自身相对模型中心"的水平方向
  向外推开 0.9*(t-0.45)/0.55，离中心越远的推得越多。

要求：
- 用 requestAnimationFrame 做缓动，lerp 系数 0.12，不要用 GSAP（减少依赖）
- 提供一个 setExplode(t) 方法，t 可以是 0/0.5/1
- 底部一个 range 滑杆绑定这个 t（触摸友好，高度 ≥ 48px）
- 两个按钮：「复位」= setExplode(0)，「清单」= 相机拉正、构件按网格排布

验收：拖动滑杆来回，没有抖动、没有构件穿插错位；复位后与原位置完全一致。
```

> ⚠️ 注意：阶段 B 的"径向散开"要基于**初始位置**算方向，不能在每帧基于当前位置算，否则会累积漂移。这是 AI 最容易写错的地方。

## 五、任务 4：点击拾取 + 构件释义

```
用 Raycaster 做点击拾取：
1. 只在 pointerup 时触发，且要求 pointerdown→pointerup 的位移 < 8px
   （触屏上点击会带 5-15px 位移，用 click 会误触发）
2. 射线只与构件数组求交，不要传整个 scene
3. 命中后：
   - 清掉上一个选中构件的 emissive
   - 给当前构件 material.emissive 设为 0x5a3a10（暖色微光）
   - 从 PART_INFO 数据表里按 mesh.name 查出释义，填到右侧信息面板
4. 面板内容：构件名（含拼音）、白话定义、深度解读、来源标注
5. 点到空白处关闭面板

注意：如果多个构件共用同一个 material 实例，改 emissive 会全部变色。
请在加载时检测并 clone 材质，或提示我模型需要修改。

验收：连续点 10 个不同构件，高亮始终只有一个；面板内容与构件对应无错位。
```

## 六、任务 5：读法闯关（产品灵魂）

```
做一个四步引导式交互，教会观众读懂一朵斗拱：

Step 1 定位：全殿轮廓中高亮"前檐柱头铺作"，问"这朵斗拱在哪儿？"
  选项：柱头 / 补间 / 转角。答对进入 Step 2。
Step 2 数跳：镜头贴近斗拱侧面，问"从栌斗开始，向外挑出了几层？"
  观众点数字 1-5。正确答案 4（双杪双下昂）。
  【重要】答错时不要只说"错了"，要播放一段 3 秒动画：
  逐跳高亮华栱/昂，并弹出"第1跳…第2跳…第3跳…第4跳"标签。
Step 3 套公式：显示"铺作数 = 跳数 + 3"，观众拖滑块算 4+3=7。
  正确后炸开一个小庆祝（粒子/光圈），显示"七铺作"。
Step 4 判偷心：镜头聚焦第一跳跳头，问"这里放了横栱吗？"
  答"没有" → 显示"偷心造"并解释；答"有" → 高亮空位说明为何是偷心。
完成：拼出完整称谓"七铺作双杪双下昂单偷心造"，解锁拆解模式。

要求：进度条固定在底部（1/4）；每步都能"返回上一步"；状态用纯 JS 对象管理，
不要引入状态库。

验收：完整走通 4 步 ≤ 90 秒；答错路径不卡死；刷新后从头开始（不做持久化）。
```

## 七、任务 6：受力流线（差异化关键）

```
做一个"力是怎么传下去的"可视化开关：
- 开启后，沿 屋面 → 槫 → 栌斗 → 华栱/昂 → 柱身 → 地面 的路径，
  用粒子流（Points）或管道流光（TubeGeometry + 移动的贴图 offset）显示力的传递
- 粒子沿预设的 CatmullRomCurve3 路径运动，速度可调
- 同时做一个"杠杆演示"：一根下昂，鼠标/手指拖动屋面端下压，
  另一端（昂尾）上翘并压住内柱，旁边实时显示文字：
  "昂尾压在梁下，中间承下平槫，作用如一根斜梁"
- 提供"关掉斗拱"的对比开关：屋顶视觉下沉（仅示意，不代表真实力学计算）

重要：界面必须有小字标注"力学示意，非有限元计算结果"。

验收：粒子流不穿模；拖动杠杆时帧率不掉；两处标注都在。
```

## 八、任务 7：性能与鲁棒性

```
给现有项目加一层"展项级"保障：
1. 启动时检测 GPU：读 renderer.capabilities.maxTextureSize 与
   WEBGL_debug_renderer_info；低配设备自动关闭阴影、贴图降级
2. watchdog：主线程每 2s 打一次心跳；若页面 10s 无响应或报错 3 次，
   自动 location.reload()
3. window.onerror / unhandledrejection 捕获，显示友好提示页，3s 后自动恢复
4. 30s 无操作 → 回首页并重置状态（展项标配）
5. 页面禁用右键、禁用文本选择、canvas 设 touch-action: none
6. 加 stats.js（仅 dev 模式）显示 fps/drawcall/三角面

验收：断网状态下全流程可用；连续操作 30 分钟内存不持续增长；
低配模拟（用 Chrome DevTools 降 4x CPU）仍 ≥ 30fps。
```

## 九、任务 8：AI 讲解（可选模块）

```
做一个"按身份讲解"的模块（前端 + 后端接口分离）：
- 首页选身份：小学生 / 中学生 / 建筑专业 / 亲子 / 老年人
- 选中同一个构件（如栌斗），五种身份显示不同深度与语气的文案
- 文案不调 API 也能用：预置 5 套本地文案（断网兜底）
- 若能联网，调用大模型按身份改写，但：
  1. 提示词里必须注入该构件的"事实卡"（name_cn/definition/detail/source）
  2. 明确要求"不得增减史实，只改变表达方式与详略"
  3. 返回内容必须带来源字段
- 每条讲解下方固定显示"依据：XXX"

验收：断网时五套文案均正常；联网改写后事实无变化（人工抽查 10 条）。
```

## 十、用来"审"AI 的三句话（每次代码回来都问）

1. **"这段在低配设备上会掉帧吗？为什么？"**
2. **"如果模型里有 60 个构件共用同一个材质，这段高亮逻辑会怎样？"**
3. **"把这段删掉，功能还能用吗？如果能，为什么当初要写？"**

> 第三句最有用。AI 写代码最大的问题是过度设计——三层抽象、四个工具函数，最后没人看得懂。学生要能讲清每一行为什么存在。

## 十一、禁忌清单

- ❌ 让 AI 决定斗拱的形制细节（它会把偷心造画成计心造，把七铺作写成六铺作）
- ❌ 让 AI 生成历史叙述（会编出不存在的事件）
- ❌ 直接使用 AI 生成的 3D 模型做结构讲解（拓扑错、榫卯假）
- ❌ 相信 AI 说的"60fps 没问题"（必须在目标设备实测）
- ❌ 一次让 AI 写整个项目（一定写到一半就跑偏，改成任务分解）
