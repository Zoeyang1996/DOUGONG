## 二、命名规则

```
<项目/资产组>-<构件类型>-<版本或编号>.fbx
```

| 段 | 取值 | 含义 |
|---|---|---|
| 组 1 | `baoguosi` | 本项目原创建模，保国寺大殿系列 |
| 组 1 | `puzuo` | 铺作单体集（另一来源） |
| 类型 | `zhutou-puzuo` / `bujian` / `zhuanjiao` | 柱头铺作 / 补间铺作 / 转角铺作 |
| 类型 | `guoleng-column` / `guoleng-joint-section` | 瓜棱柱组合 / 榫卯剖段 |

**为什么用英文名**：中文文件名在 Unity / UE / three.js 的某些管线里会出现编码或路径问题。全 ASCII 是跨软件最稳的做法，中文对照以本文件为准。**对象名内部完整保留中文**（如 `B01_栌斗`、`东次间小藻井_上八角井`），导入后不会丢。

## 四、使用前必读的 5 条

**1. `baoguosi-hall-interior-v01.fbx` 是超重资产（30.7 万面 / 2869 个对象）。**
直接丢进 three.js 会掉帧。它是"结构完整度"的底稿，实际用于网页时必须先减面或按构件集合分批加载。单场景预算 < 30 万面。

**2. 全部材质是纯色 PBR，没有贴图。**
木纹要靠后续贴图或程序化材质加，别指望 FBX 里有木纹。

**3. `puzuo-zhuanjiao-01` 与 `-02` 内容完全相同**（同 104 网格、同 3406 面）。源文件是两个另存副本，保留两份只为不丢东西，用一份即可。

**4. `puzuo-zhutou-01.fbx` 里有个源文件笔误：`B01_櫍斗` 应为 `B01_栌斗`。**
按"不改动原作者资产"的原则未修正，导入后可自行改名。

**5. B 组（铺作单体集）的尺度有差异，不要直接混排。**
`puzuo-zhutou-01` 含 4.96 m 立柱、`-02` 柱身 5.55 m，而 `-03` 是纯铺作（1.5 × 2.2 × 2.8）。要做同比例尺对比（幕 5 的三朵并排），必须先统一基准 —— 建议以**栌斗底面中心为原点、材宽为标尺**对齐。

## 五、给 three.js 的下一步建议

1. **FBX 是交付与交换格式，不是网页格式。** 上线前转 GLB：`npx gltf-transform optimize in.fbx out.glb`（先经 Blender 转 glTF 更稳）。
2. 转 GLB 时开 Draco 压缩 + 贴图 WebP/KTX2，单朵铺作目标 < 3 MB。
3. `baoguosi-zhutou-puzuo-v01` 的 59 个对象已按 `dou_/gong_/ang_/fang_` 命名，可直接作为爆炸图与拼接关卡的构件索引（对应 `models/baoguosi_zhutou_v01/parts_manifest.json`）。
4. 层级不要丢：FBX 里保留了父子关系与集合拆分，转 GLB 时注意 `use_selection=False` 且保留空物体，否则层变换会丢。
