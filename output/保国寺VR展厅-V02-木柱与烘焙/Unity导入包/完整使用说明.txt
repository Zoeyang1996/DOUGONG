   每根木柱的柱础、柱身和托木已归为 ColumnGroup_Zone 分组，可整组移动；顶部连系梁独立保留。
   实拍 PBR 贴图已打包进 blend，外部原图也在“贴图_PBR”中。

2. 查看已经烘焙的效果：
   模型/展厅V02_烘焙展示_无摄像机.blend
   这份用静态光影贴图显示，已移除灯和摄像机。按材质预览查看即可。
   运行网格按 8 个展区合并；墙面文字保留为独立网格。

3. 交给 Unity 同学：
   使用“Unity导入包”中的 Assets/BaoguosiGalleryV02 文件夹。
   不要只拷贝一个 FBX，否则会缺少贴图和材质配置工具。
   独立 FBX 也在“模型/Baoguosi_Gallery_V02_Baked.fbx”，配套“贴图_烘焙”一起使用。

二、Unity 操作（Built-in / URP）
1. 打开自己的 Unity 工程。
2. 将“Unity导入包/Assets/BaoguosiGalleryV02”整个文件夹复制到工程 Assets 目录。
3. 等待模型、贴图和编辑器脚本导入，工具会自动建立并关联烘焙材质。
4. 点击 Unity 顶部菜单：
   榫卯智言 → 展厅V02 → 2 创建展厅场景（无摄像机）
   会另建并保存一个场景，原有场景不会关闭。文件保存在该资源包的 Scenes 中。
5. 如果后来切换 Built-in / URP 或材质丢失，点击同一菜单下的“1 配置或修复烘焙材质”。
6. 点击“3 检查已导入资源”，核对贴图、材质及摄像机检查结果。
7. 将自己的 XR Origin / PICO 交互系统接入该场景，再设置移动、瞬移、碰撞和游戏操作。
   此次交付是展厅场景资产，不包含已连接的 VR 游戏逻辑、碰撞系统或头盔安装程序。

三、这次“烘焙”的准确含义
已用 Blender Cycles 计算材质颜色、直接光、间接光和自发光，并保存成 8 张彩色静态光影贴图：
主展厅和大殿挑战区各 4096×4096，其余 6 个展区各 2048×2048。
新增木柱造成的遮挡和阴影参与了计算；不是仅贴木纹或只做 AO。

为了跨 Unity 渲染管线交接，静态光影与表面颜色合并为显示贴图，Unity 使用 Unlit 显示。
因此展厅本体不需要重新打实时灯；后来加入的角色、斗拱或其他动态展品可以单独打灯。
这不是 Unity 自己生成的 LightingData.asset，也不包含 Unity 原生光照探针。
FBX 本身不能完整传递这类 Unity 工程设置，所以需要配套贴图和材质配置工具。

贴图已经包含本次曝光和色调效果。请检查现有工程的全局后期、曝光和色调映射，
避免对这些贴图再次处理而改变明暗；工具不会擅自更改现有项目的这些全局设置。
Unlit 展厅本体不会接收后来加入的实时阴影或灯光。
如果需要实时反射、动态阴影或重新改灯，请用可编辑 PBR 源文件重新制作 Unity 材质并在 Unity 烘焙。
修改墙、柱、展台位置后，也应重新烘焙；仅移动已经烘焙的网格会使阴影和实物不一致。

四、本次空间修改
保持 36×24 米的单层虚拟展馆与原有分区、回游动线、墙面文字、空展台。
新增 24 根独立木柱、石质柱础、简化柱头托木，以及相应的顶部连系梁。
这些构件是数字展厅的现代木构意象，不应当作保国寺宋构实测复原依据。
新增柱础已检查与原主线、静廊路线的间距；主厅一个瞬移定位点已移开柱础。
所有最终 Blender 文件、FBX 均无摄像机；预览图用临时摄像机渲染，随后删除。

五、贴图、文件与验证
贴图_PBR：实拍木纹、石材和矿物墙面原图，来自 Poly Haven，CC0，可随工程交接。
贴图_烘焙：只供静态展示版本使用的光影图集。
预览：实际模型渲染，以及关闭所有灯光之后的烘焙显示验证。
检查记录：模型重开、FBX 回导、贴图与摄像机检查、烘焙参数、柱子与动线记录。
编辑源文件：场景修改、烘焙及检查的制作脚本；普通 Unity 接手同学不需要运行。

这台电脑没有 Unity 编辑器，所以未在真实 Unity 工程或 PICO 头盔运行验证。
编辑器工具已通过 C# 6 语法解析，但尚未由 Unity 编辑器进行 API 编译。
已进行的检查以“检查记录”中的实际结果为准。当前兼容工具以 Unity 2022.3 常用 API 编写，
支持 Built-in 和 URP 的材质选择；未承诺任意旧版 Unity、HDRP 或第三方管线可直接使用。
导入工具已为 Android 设置 ASTC 6×6 贴图压缩和 mipmap，供 PICO 项目使用。
PICO 性能还需在目标头盔测帧率，按实际项目调整贴图压缩、后期和动态展品开销。
