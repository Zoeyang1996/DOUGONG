# 隆兴寺摩尼殿 · Blender 高精度复原工程

> 北宋皇祐四年（1052）建，河北正定隆兴寺摩尼殿。
> 面阔七间、进深七间，平面呈十字形（四面出抱厦 / 龟头屋），重檐歇山顶。

## 二、形制判读（建模依据）

开工前先依据四张参考图与航拍图判读形制，确定了几何骨架：

1. **平面为十字形**——航拍图（第 4 张）显示主体四面各凸出一间「抱厦」，形成十字；抱厦面阔约为主体三分之一。
2. **重檐**——正立面（第 1 张）中部有一条贯穿全宽的绿色腰檐（下檐），其上再起大屋顶（上檐）。
3. **四抱厦各为歇山，山花朝外**——第 2 张仰视图给出关键证据：抱厦屋顶正对镜头的是一个红色三角形「山花」，两侧为陡峭的坡面，山花下缘两端各有一个绿色脊兽（博脊端兽）。这正是「抱厦（龟头屋）用歇山、山花朝外」的典型做法。
4. **上檐为歇山，正脊沿面阔方向**，两端鸱吻；山面撒头较小，山花偏窄。
5. **斗拱硕大**——檐下斗拱高度接近檐柱的 1/5，是宋代官式做法特征。
6. **色彩**：绿琉璃筒瓦屋面、朱红抹灰墙、深褐木构、灰白石台基。

据此反推主要尺度（以照片中抱厦宽度与总高比例标定，取整）：

| 主体面阔 | 33.0 m（七间） |
| 主体进深 | 26.0 m |
| 抱厦 | 面阔 11.4 m，外伸 4.6 m，檐口 +9.85 m，正脊 +14.60 m |

## 三、建模方式

**全部为参数化程序建模（Python + bpy 直接生成网格）**，而非手工雕刻。这样做的原因是：古建的重复构件（瓦垄、斗拱、椽当、脊件）数量极大，手工建模既不可能精确，也无法保证四面完全对称；程序生成则可以让「一个参数改动、整栋建筑同步」。

代码分为五个生成器：

### 1. 歇山曲面生成器（`roof.py`）
这是整个工程的核心。屋面不是简单放样，而是用解析曲面表达宋式屋面：

```
z = He + rise · f(a) · h(b)
```

- `a` = 距前后檐口的水平距离，`b` = 距山面檐口的距离；
- `f` 为**举架曲线** `f(u)=0.62u+0.38u^2.05`：檐口起步约 5 举（≈27°），越靠近正脊越陡，形成中式屋面特有的凹曲；
- `h` 为撒头收敛函数：`|x|>LR` 时屋面按比例向山面檐口收束，自然生成歇山两端的小坡（撒头）；
- **山花**：把 `z>Hg` 且 `|x|>LR` 的网格面**整片剔除**，由一块独立的三角山花板（带实心菱形悬鱼与短须）封堵——比「把顶点折到山花平面」更干净，不会因折边产生锯齿。
- **翼角起翘**：叠加高斯项 `A·exp(-(d_corner/R)²)`，使檐口在角部柔和上扬；
- **瓦垄**：沿曲面法向做余弦位移（周期 0.355 m，幅度 0.062 m），配合 8 段圆柱生成的**瓦当**排布在檐口，形成照片里那种起伏的、带圆瓦头的檐口线。撒头方向的采样密度按瓦垄周期取（0.09 m），否则会出现摩尔纹状的锯齿。

### 2. 腰檐生成器（`skirt.py`）
重檐下檐沿十字平面环绕，用「到檐口的最近距离」构造坡面，再按上层墙位置裁切。

**抱厦处的开口是本工程最费斟酌的一处**：下檐不能矩形硬切（会留下透视黑洞），也不能完全不开（抱厦山花会被下檐挡住）。做法是逐面比较「该处抱厦屋面高度」与「该处腰檐高度」，只在下檐**低于抱厦屋面**的区域开口，开口边界因此自然落在两者相交的天沟线上；再让阈值留 0.6 m 的重叠量，使下檐像瓦片一样压在抱厦屋面之上，看不出切口。

### 3. 斗拱单元（`dougong.py`）
按宋式「五铺作双抄单下昂」意象，用约 20 个带卷杀的箱体组成一朵：栌斗→泥道拱/华拱一抄→散斗→慢拱/华拱二抄→下昂（含昂嘴）→令拱→耍头→替木。单朵是一个函数，沿檐线按 1.3–1.5 m 间距阵列，四面向心旋转，慢拱端头正好首尾相接，转角自然咬合。下檐约 90 朵，上檐约 80 朵，抱厦另计。

斗拱背后另加一道**拱眼壁**（`arch_panel`，深色连续板）。这一件不加的话斗拱会像一排悬空的小方块；加上之后整条檐下变成「板—斗拱—撩檐枋」三层，正是照片里的观感。

### 4. 墙体与门窗（`walls.py`）
带洞口的墙板生成（自动切分为洞口两侧与上方墙片）、檐柱（带收分与柱础）、额枋/平板枋、直棂窗（外框＋密集竖棂＋暗板）。

**门洞是一个统一的总成 `portal()`，有门与无门共用同一套尺寸**——这是这一轮重点重构的地方。函数只接收「洞口宽 `w` × 高 `hh`、洞底 `zb`、墙面外皮 `face`、外法向 `out`」，内部按同一套规则推导所有构件：

| 构件 | 推导规则 | 有门 | 无门 |
|---|---|---|---|
| 立颊（左右门框） | 由洞口边向洞内吃 `jamb=0.36`、向墙内咬 0.04 | ✓ | ✓ |
| 上槛 | 洞顶向下 `head=0.26`，向上咬 0.04 | ✓ | ✓ |
| 门槛（石） | 洞底起 `sill=0.22`，外凸 0.025 | ✓ | ✓ |
| 板门两扇 | 净空 `(w-2·jamb) × (hh-head-sill)` 一分为二，四周留 12 mm 门缝，凹入框内 0.055 | ✓ | — |

所以两种情形**洞口、框料、门槛完全一致**，差别只在于净空里有没有门扇：`door=True` 时门扇严丝合缝填满净空（旧版门扇比洞口窄 8 cm、矮 10 cm，四周漏出黑缝，远看就是一块红板），`door=False` 时净空敞开成一条可穿行的门道。开关是 `params.BS_DOOR`，改一个布尔值即可整体切换，重建脚本不需要任何其它改动。

门扇 `door_leaf()` 也一并重写：以**外表面坐标** `face` 加外法向符号 `out` 定位，门板向 `-out` 取厚，门钉（7×7 圆钉，`cyl_dir` 生成，凸出 2.8 cm）与铺首一律贴在**外表面**。旧版用 `face + 0.09*tdir` 定位五金，抱厦的 `tdir=-1` 恰好把 81 颗门钉和一个铺首全埋进门板内部——这就是「有门版本看着像没门」的直接原因。

殿身四面的门道（抱厦与殿内之间）同样调用 `portal(..., door=False)`，与外檐门洞同宽同高，因此从敞开的抱厦望进去，是一条装了门框、有进深的门道，而不是一个 11.2 m 宽的通高破洞（旧版做法）。

### 5. 脊饰（`roof.py` 内的 `build_zhengji / build_chiwen / build_gable_ridges`）
正脊为三层叠砌＋脊筒节奏；鸱吻用一条 J 形路径分段放样、截面渐缩，加背鳍与剑把；垂脊沿山花边缘扫掠，戗脊从山花底角扫到檐角，端头加翘头与走兽；博脊压在山花下皮并置端兽。

> 抱厦的四套构件只建一套，其余三套以**链接副本**（共享网格数据）旋转 90°/180°/270° 布置——既保证四面严格一致，也把文件体积压到 5.6 MB。若需单独修改某面，`物体 → 关系 → 设为单一用户` 即可断开。

## 四、材质与贴图方案

**没有使用任何外部素材**，7 张贴图全部用 numpy 生成，且都写成「正弦叠加的周期函数」，因此**天生无缝可平铺**：

| 贴图 | 尺寸 | 生成思路 | 用途 |
|---|---|---|---|
| `T_roof_tile` | 1024² | 顺坡拉长的低频噪声（釉色斑驳）＋高频釉光块＋灰白风化＋积水污痕 | 琉璃绿瓦 |
| `T_wall_red` | 1024² | 朱红基底＋斑驳＋竖向雨痕（各向异性噪声）＋泛白风化 | 朱红墙面 |
| `T_wood_dark` | 1024² | 年轮正弦＋纵向拉伸噪声 | 斗拱、椽子 |
| `T_door_red` | 512² | 暗红漆面＋木纹 | 板门、红柱 |
| `T_stone` | 1024² | 色斑＋麻点（随机亮点） | 台基、踏跺、石桥 |
| `T_caihua` | 512² | 青绿叠晕条带＋白粉界线 | 彩画（备用） |
| `T_ground` | 512² | 砖石色斑 | 地面 |

**投影方式**：全部使用 **Object 坐标 + Mapping 缩放**做盒式投影，**完全不依赖 UV**。这意味着任何新加的构件（哪怕是一块临时补的板）都会自动获得正确尺度的贴图，不会出现拉伸或接缝——对需要反复修改的方案阶段非常重要。

**材质参数**（Principled BSDF）：

- 琉璃瓦：粗糙度 0.46、Specular 0.32、贴图同时接入凹凸（强度 0.18）——保留釉面高光但不至于变成镜面；
- 朱红墙：粗糙度 0.84，几乎全漫反射，仅靠贴图的明度变化出体积；
- 斗拱：把木纹贴图用乘法提亮到朱漆色（tint ≈ 3.5），粗糙度 0.60——檐下很暗，材质若照写实取深褐就只剩一团黑影，提亮后才能在阴影里看出层次；
- 拱眼壁：暗朱红纯色（0.155/0.062/0.048），比斗拱暗一档，形成「浮雕压在底板上」的关系；
- 石活：粗糙度 0.9。

**光照**：太阳（4.2，色温偏暖）＋世界环境＋8 盏檐下补光。环境做了**光线分离**——相机射线看到的是明亮的渐变天空，照明射线只取 95% 强度的冷色环境光，这样既保证了照片般的天空背景，又不会让檐下阴影被天光洗成蓝灰色（这是写实渲染里最常见的失真）。

另外每座抱厦配两组面光源（门口一组 200 W、匾额与檐下一组 190 W），模拟地面反射光，避免檐下与门扇陷进死黑。需要说明的是：**门扇曾经「消失」并不是光照问题**，而是五金被埋进门板内部、门扇又比洞口小一圈，露出来的只有一片没有细节的红板；这一轮改的是几何，不是灯。

## 五、还原精度与取舍

### 做到的部分
- **平面与层数**：十字形平面、四面抱厦、重檐、四抱厦各为歇山且山花朝外——与航拍图逐项对得上；
- **比例**：面阔/进深/檐高/脊高按照片标定，抱厦面阔约为主体的 2/5，下檐高度约占总高 45%；
- **屋面细节**：举架凹曲、翼角起翘、瓦垄与瓦当、正脊/垂脊/戗脊/博脊、鸱吻、山花悬鱼、博脊端兽；
- **斗拱**：朵型、层数、出跳、阵列间距按宋式比例；
- **门窗匾额**：板门（7×7 铜钉、铺首、门框、上槛、门槛）、竖匾「摩尼殿」（字体转为网格，不依赖系统字体）。

### 已知偏差（诚实说明）
1. **无实测数据**。所有尺寸由照片透视反推＋宋《营造法式》比例校正，与原构存在 5%–10% 的尺度误差；尤其屋脊总高，照片仰视透视会放大，我取了偏保守的值。
2. **抱厦屋面与上檐的交接做了简化**。真实做法是「天沟」——抱厦屋面在上檐坡面上被斜切收头。本工程让抱厦屋面（脊 16.45 m）略低于上檐檐口平面（16.58 m），二者自然相压，正面完全看不出差别，但**从正上方俯视能看到抱厦后坡没入上檐**，这是刻意的取舍（做布尔天沟会显著增加面数且极易破面）。抱厦与**下檐**的交接则已按真实天沟线开口处理（见第三节）。
3. **斗拱是「意象复原」而非逐件测绘**。一朵斗拱 20 个构件，比例按宋式，但卷杀曲线、昂嘴角度、拱瓣数均为概括处理，近看仍能看出是方箱拼合。
4. **屋面瓦垄是「位移」而非「一块块瓦」**。用曲面法向的余弦位移模拟筒瓦起伏，檐口再补圆形瓦当；远看几乎乱真，贴近到 1 m 内能看出瓦是连长在一起的。
5. **未建模的部分**：室内梁架（用暗腔体代替，避免透过门洞看到透空）、檐下椽子与飞子（檐底为暗面）、石经幢、树木与僧人。这些在参考照片里存在，但不属于建筑本体。
6. **彩画**：真实摩尼殿斗拱、额枋上有清代所绘的青绿旋子彩画，本工程斗拱统一按朱漆处理，彩画材质已备好（`彩画`）但未大面积使用——因为照片里檐下过暗，彩画几乎不可辨，强行加上反而失真。
7. **抱厦山花的比例偏大**。受限于整体标高（抱厦脊高被压在 16.45 m 以内，以免盖过上檐檐口），山花三角形比实物显得略宽；若放开标高限制可以让它更接近照片。
8. **匾额为示意**。「摩尼殿」三字用微软雅黑 Bold 转网格（不依赖系统字体），笔画与宋代原匾的书法相去甚远，仅作位置与体量的示意。

### 如果要继续提高精度
- 用实测图纸替换 `scripts/params.py` 里的全部尺寸（改完直接重跑即可重建）；
- 为斗拱增加「单朵可参数化」的昂嘴/卷杀曲线；
- 把屋面位移改为真实的筒瓦+板瓦两层几何（面数约 ×6）；
- 补室内梁架与椽子，用 Cycles + 贴图烘焙出室内漫反射。

## 六、如何修改

1. **改尺寸**：编辑 `scripts/params.py`，然后
   ```
   blender -b --python scripts/build.py
   ```
   会重新生成 `隆兴寺摩尼殿.blend`（约 3 秒）。
2. **改材质**：直接在 Blender 的着色器编辑器里改；贴图已打包，替换 `textures/*.png` 后重新载入即可。
3. **改单独构件**：所有物体按 9 个集合分类，中文命名，直接选中编辑；抱厦为链接副本，需先「设为单一用户」。
4. **切换有门 / 无门**：`scripts/params.py` 里 `BS_DOOR = True` 为装板门，`False` 为开敞门道；两种配置共用同一个 `portal()`，洞口、门框、上槛、门槛尺寸一致，只是净空里有没有门扇。门洞尺寸则统一由 `BS_PORTAL_W / BS_PORTAL_H` 控制，抱厦外檐与殿身门道同时生效。
5. **换视角出图**：`scripts/final_render.py` 里 `VIEWS` 字典改相机位置/焦距，运行即可（也可只出某几张：`... -- 06_板门细部`）；或者先跑 `scripts/preview.py`（900×580 / 32 采样）快速检视四个角度再定稿。

## 七、迭代记录

第一版出图后逐张比对，改掉了以下硬伤，均已写进代码：

| 问题 | 现象 | 处理 |
|---|---|---|
| 下檐矩形硬切 | 抱厦与腰檐交界处出现黑色透视洞 | 改为按「抱厦屋面高于腰檐」逐面开口，边界落在天沟线上 |
| 门扇朝向 | 板门法向偏 90°，门洞成纯黑 | `door_leaf` 改用 `axis` + `out` 双参数定义朝向 |
| 匾额位置 | 悬空在撩檐枋外 2.3 m，或后来被埋进墙里 | 定在墙外皮 +0.22 m，尺寸 1.46×2.62 m |
| 转角空档 | 两行斗拱在角部交汇留缝 | 四角各加一朵 45° 转角铺作 |
| 斗拱悬空 | 一排孤立方块，檐下一片死黑 | 加拱眼壁底板 + 提亮朱漆材质 + 每抱厦两组檐下补光 |
| 悬鱼 | 与山花同色，只剩一个「X」轮廓 | 独立材质提亮，实心菱形几何，下悬短须 |
| 瓦垄锯齿 | 撒头方向采样密度不足，边缘呈锯齿 | `res_y` 从 0.22 提高到 0.09（上檐 0.13） |
| 补间过密 | 相邻斗拱慢拱互相穿插成一团 | 间距 1.5→1.85 m（上檐 1.80、抱厦 1.55） |
| 檐下泛粉 | 撩檐枋/额枋受光后偏粉 | 朱漆 tint 压到 0.90，补光降到 190 W 并偏冷 |
| **有门/无门两套逻辑** | 门扇比洞口窄 8 cm、矮 10 cm，四周漏黑缝；五金按 `tdir` 偏移被埋进门板里，从外面看门就是一块光板 | 抽出统一 `portal()`；门扇按净空精确下料；五金改贴外表面；殿身门道同参数、`door=False` |
| 门槛被埋 | 墙基通长，把洞口下口 32 cm 砌死，门扇下缘陷进石活 | 墙基在门洞处断开，门槛独立按洞口净宽下料 |

面数因此从 13.9 万增到 23.8 万，文件从 5.6 MB 增到 7.7 MB，构建时间仍约 3.4 秒。

**如何切换有门 / 无门**：改 `scripts/params.py` 里的 `BS_DOOR = True/False`，再跑一次 `blender -b --python scripts/build.py`。两种配置的对象数分别为 112 / 105（含 9 盏灯与 1 台相机），除门扇与五金外，洞口、门框、上槛、门槛完全一致。

## 八、第三轮：屋顶几何重写（当前版本）

第二轮出图后，用户指出「都破了」。逐张定位后确认不是贴图或光影问题，而是**屋面拓扑本身错了**，于是把屋顶从底重写。

### 8.1 破损的根因

`roof.py` 旧版 `build_xieshan()` 有这么三行：

```python
keep = ~((np.abs(fx) > S.LR) & (fz > S.Hg))   # 删掉撒头所在区域的面
faces = faces[keep]
```

它把「|x| > LR 且 z > Hg」的面整片删掉——**等于把撒头整个挖走**，而山花板只封在 `|x| = LR` 这个平面上。于是从上方可以顺着山花两侧直接看进殿内，正立面则能看到一条褐色空洞。诊断脚本数出来的边界边：`屋顶_上檐` 1882 条、`屋顶_下檐` 2800 条、每座抱厦 1026 条。

另外两处同源问题：

- 腰檐用 `zc < top_z` 裁上端 → 上端是一条**锯齿状等高线**，且这条线并不在上层墙面上（比墙外皮大 2.5 m），檐口悬空露缝；
- 腰檐再按 mask 挖掉四抱厦 → 又一圈锯齿开口，Solidify 沿开口生成亮边，俯视是一圈白毛刺。

### 8.2 重写后的几何

**屋面（`roof.py`）**改为纯粹的解析曲面，不再删任何面：

```
正坡   main = He + rise · f(a/HD)                       f(u) = 0.60u + 0.40u²
撒头   side = He + (min(main, Hg) − He) · f(b/(HW−LR))
屋面   Z = main (|x| ≤ LR) ／ side (|x| > LR)
```

- 上部分（`z > Hg`）是悬山：两坡相交成正脊，两端各一块垂直山花；
- 下部分（`z < Hg`）是庑殿：撒头从 `Hg` 这条水平线落向山面檐口；
- 两者在 `|x| = LR` 处靠山花板封住，**曲面处处连续、整体闭合**；
- `|x| = LR` 强制插入网格列，折角处瓦垄位移归零，避免折线处出现噪点；
- 所有屋面为「曲面 + Solidify」，生成后统一 `bmesh.ops.recalc_face_normals` 求外法向。

**腰檐（`skirt.py`）**改为极坐标闭合环实体：外圈是檐口矩形、内圈贴上层墙身，上下两层封口，因此不可能有开口。四座抱厦用**布尔差集**（`build.boolean_cut()`，EXACT 求解器，操作数取 depsgraph 求值后的实体网格）真实切掉——矩形缺口切不出抱厦屋面的曲面边界，会在两者之间留一块红三角（上层墙透出来），布尔差集则让断口正好落在抱厦屋面上，交界是一条干净的天沟。

### 8.3 本轮其余修正

| 问题 | 现象 | 处理 |
|---|---|---|
| 撒头被挖空 | 山花两侧是褐色空洞，俯视可看进殿内 | 删除「删面」逻辑，撒头按 `min(main,Hg)` 生成，曲面闭合 |
| 腰檐锯齿 | 檐口上端一条锯齿等高线 + 白毛刺 | 极坐标闭合环，不再裁切、不再挖洞 |
| 腰檐断面露红 | 矩形缺口与抱厦屋面之间漏出上层墙 | 布尔差集，断口贴抱厦屋面 |
| 抱厦内山花外露 | 3/4 视角屋顶上浮着一块红三角 | 抱厦只建外端山花（`gable_signs=(1,)`） |
| 抱厦山花过窄 | 宽高比 2.09，照片实测 2.19，视觉上像一块立起来的板 | 撒头底线 `Hg`、收山量联合标定到 2.35 |
| 下檐断开成两截 | 抱厦处腰檐中断、两侧断口对不齐 | 闭合环 + 布尔切分，正立面成一条连续水平带 |
| 正脊过短 | 上一版把正脊压到 8.2 m，屋顶像破庑殿 | 通长 26.4 m（占通宽 86%） |
| 鸱吻不像 | 太细太高，像两根鱼刺 | 截面加宽到 ±0.62，`ss` 收分重排 |
| 悬鱼像十字架 | 两片横臂叠出一个「十」字 | 改为主轴 + 中央大菱形 + 上下小菱形 + 两侧圆头，五片凸多边形 |
| 斗拱细碎 | 远看是一排小方块 | 单朵放大到 h=1.10、出跳 0.74，间距放宽到 1.92；三道拱枋加厚 |
| 匾额臆造 | 照片里抱厦只有三樘门洞，无匾 | 移除 `build_plaque` 调用 |
| 台基发灰 | 照片是暖调石材 | 石材 tint 加到 (1.08, 1.00, 0.88)，地面 (1.10, 1.02, 0.90) |
| 博缝过亮 | 山花边缘一条刺眼白边 | 压到 (0.188, 0.182, 0.168) |

面数 23.8 万 → 30.1 万，物体数 131 → 115（抱厦内山花去掉 16 件），构建 3.5 s → 7.1 s（四道布尔）。

### 8.4 仍然存在的差距

1. 抱厦撒头与腰檐的交界，目前靠实体互穿，缺少一条真实的「天沟」瓦沟线；
2. 山花板的博缝只在两侧斜边有，底部（与撒头相接处）没有博脊；
3. 斗拱是意象化拼块，不是严格的五铺作双抄单下昂材份；
4. 墙面为单一朱红，缺少照片里的柱列节奏与风化层次。
